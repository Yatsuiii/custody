# Context Summary: Optional Extractor Contract Implementation

## Current

The governing design, merged in PR #2475 on 2024-12-10 (commit `ec75ee38274ed5423ece5f3ae0b6e947a7e6ec43`), replaces the blanket optional-extraction behavior with separate `OptionalFromRequest` and `OptionalFromRequestParts` traits implemented only for types where discarding a specific missing-value error makes sense (Source: PR #2475, Issue #2298). For `TypedHeader`, the merged implementation distinguishes missing headers (returning `Ok(None)`) from present-but-malformed headers (returning `TypedHeaderRejection`) (Source: PR #2475). The merged changelogs confirm that `Option<Path<T>>` and `Option<Query<T>>` no longer swallow all error conditions (Source: PR #2475).

## History

The superseded design, captured at baseline SHA `fd11d8efde4895a2159a29dcd586a7db99917057`, used a blanket `FromRequestParts` implementation for `Option<T>` that called `.await.ok()`, collapsing every rejection to absence (Source: Pinned code snapshot, `axum-core/src/extract/mod.rs`). Issue #2298 identified that this blanket behavior caused users to expect different semantics for particular extractors (Source: Issue #2298). Maintainer David Pedersen approved the proposed trait-separation approach with "I think that sounds like a good path!" (Source: Issue #2298, comment 1872592684). PR #2475 deprecated the old optional wrappers (Source: PR #2475).

## Scope

The task requests implementing the extractor-specific contract for `TypedHeader` so `Option<TypedHeader<_>>` has deliberate behavior for both absent and malformed header values, plus focused tests covering an absent `Content-Type` header and a malformed `Content-Type` header (Source: Raw task prompt). PR #2475's scope included adding the two optional-extractor traits, implementing them only for relevant types, deprecating old optional wrappers, documenting the behavior, and updating changelogs (Source: PR #2475). The pinned snapshot identifies three modified source files, one new source module, and focused tests (Source: Pinned code snapshot). Baseline `axum-extra/src/typed_header.rs` already distinguishes missing headers from malformed present values in the non-optional `TypedHeader` rejection (Source: Pinned code snapshot).

## Uncertainty

The sources do not establish which specific files beyond `axum-core/src/extract/mod.rs`, `axum-extra/src/typed_header.rs`, and `axum/src/extract/mod.rs` require modification. The sources do not define "relevant types" beyond the examples `Path`, `Query`, and `TypedHeader`. The sources do not specify low-level implementation mechanics (trait method signatures, error-type relationships) beyond the high-level behavior contract (missing → `None`, malformed → rejection).
