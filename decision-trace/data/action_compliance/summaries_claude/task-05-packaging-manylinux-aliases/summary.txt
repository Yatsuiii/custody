# Current

The task must add PEP 600 perennial tag generation to `packaging.tags._linux_platforms()` for a bounded case: x86-64 Linux with glibc 2.17. The function must emit `manylinux_2_17_x86_64` down through `manylinux_2_5_x86_64` in descending preference order, followed by the generic Linux fallback (raw task). The starting code at pinned commit `pypa/packaging@19fbc45b24ca0d577c9b256bb404b0dbaf4903da` supports three discrete legacy manylinux policies but does not yet generate PEP 600 perennial tags (artifact_003). PR #293, which merged PEP 600 support, included `_LEGACY_MANYLINUX_MAP` and emitted each legacy alias directly after the corresponding `manylinux_<major>_<minor>` tag per maintainer review requirements (artifact_001, https://github.com/pypa/packaging/pull/293).

# History

PEP 600 (status: Final) established a perennial, glibc-versioned policy that replaces PEPs 513, 571, and 599, while preserving legacy tag names as aliases: `manylinux1` for glibc 2.5 on x86, `manylinux2010` for glibc 2.12 on x86, and `manylinux2014` for glibc 2.17 on supported architectures (artifact_002, https://peps.python.org/pep-0600/). The "replaces" relationship does not authorize deleting behaviors from earlier PEPs (artifact_002).

# Scope

In scope: emitting perennial tags for glibc 2.17 down to 2.5 on x86-64, refactoring glibc parsing as needed, adding a focused test in `tests/test_manylinux_pep600.py` (raw task). Out of scope: support for future glibc major versions (raw task). The task targets `_linux_platforms()` specifically, not the broader tag-generation system (raw task).

# Uncertainty

The raw task does not specify whether the generic Linux fallback already exists or requires implementation. The task does not mandate emitting legacy aliases alongside perennial tags, though PR #293 required this (artifact_001). The exact refactoring approach for glibc parsing is unspecified.
