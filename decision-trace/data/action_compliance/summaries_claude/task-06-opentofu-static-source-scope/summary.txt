## Current

The applicable design retains the module `source` attribute's unevaluated `hcl.Expression` on `ModuleCall` to support static evaluation of module sources and backend configuration attributes at init time (artifact_002: RFC in PR #1649, implementation in PR #1718 for OpenTofu 1.8). At the pinned commit `3fdc8090501234c55093078255969ecbc46f2fe2`, `internal/configs/module_call.go` eagerly decodes the source into a string and address, discarding the expression; `internal/configs/module_merge.go` propagates only address fields during override merges (artifact_003).

## History

Issue #1042 initially proposed both constant attribute evaluation and block-label interpolation (artifact_001). A maintainer requested label interpolation be removed due to rename/identity complexity; the author agreed and marked it out of scope (artifact_001: comments #1875588374, #1875655905). The accepted RFC explicitly does not authorize block-label evaluation (artifact_002). PR #1718 merged the static-evaluation base, module-source support, and backend configuration support (artifact_002).

## Scope

**In scope:** Retain the unevaluated source expression even when eager decoding reports diagnostics; preserve the expression through override merges; add a parser test proving `source = local.module_source` traversal survives decoding (task prompt). Module block labels remain fixed parser identity strings (artifact_003).

**Out of scope:** Block-label interpolation (artifact_001, artifact_002); implementing the evaluator itself (task prompt).

**Neighboring:** Backend configuration attributes also use static evaluation (artifact_002: PR #1718).

## Uncertainty

The sources do not specify how diagnostics from eager address decoding should coexist with retained expressions, the exact API changes required in `module_call.go` or `module_merge.go`, or test coverage requirements beyond the single traversal test mentioned in the task prompt.
