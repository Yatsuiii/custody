# Current

The applicable design requires implementing `encoding="locale"` support in `Lib/_pyio.py` for both `TextIOWrapper` and text-mode `open()` (raw task). At the pinned commit `261a452a`, `TextIOWrapper` does not yet recognize the `"locale"` sentinel (artifact_003). PEP 597 (Final, Python 3.10) specifies `"locale"` as a valid encoding value for `io.TextIOWrapper` and states it is not a codec alias because the locale may change at runtime and because `TextIOWrapper` has device-encoding behavior (artifact_002). The implementation must be confined to the pure-Python fallback and not modify the C accelerator (raw task). A focused regression test should be added in `Lib/test/test__pyio_locale.py` exercising both entry points (raw task, artifact_003).

# History

On 2021-03-31, commit `ff3c9739bd69aa8b58007e63c9e40e6708b4761e` changed both Python and C `open()` to allow `encoding="locale"` in binary mode (artifact_001). Later the same day, commit `cfa176685a5e788bafc7749d7a93f43ea3e4de9f` explicitly reverted that change, restoring the unconditional rule that binary mode rejects every non-`None` encoding; the final Pep remained in force while only the over-broad implementation was reverted (artifact_001). The pinned code boundary at `261a452a` precedes PEP 597's merged implementation (artifact_003).

# Scope

This is a text-encoding feature only; it does not establish an encoding parameter for binary streams (artifact_002). At the pinned commit, pure-Python `open()` rejects any non-`None` encoding in binary mode (artifact_003). The change must remain in `Lib/_pyio.py` and `Lib/test/test__pyio_locale.py` without touching the C accelerator (raw task, artifact_003). Text-mode `open()` reaches `TextIOWrapper` for text mode (artifact_002).

# Uncertainty

The sources do not specify the exact resolution mechanism for mapping the `"locale"` sentinel to the current locale encoding. They do not detail what specific test cases beyond "exercises both entry points" should appear in the regression test. The distinction between device-encoding behavior and regular locale encoding resolution is mentioned (artifact_002) but not elaborated. Error handling for invalid locale configurations is not addressed.
